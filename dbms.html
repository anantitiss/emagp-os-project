How it works

  1. Authentication: passwords are checked as SHA-256 hashes.
  2. Reference monitor: every request goes through one function that applies role-based rules first.
  3. Break-glass: if denied, a doctor (or a nurse with doctor approval) can declare an emergency with a valid reason code and gets a read-only token for the minimum data set only.
  4. Capability token: signed with HMAC-SHA256, expires after 30 minutes, can be revoked, and is checked on every read.
  5. Audit log: hash-chained, with an alert logged to the supervisor on each emergency.
  6. Review: a supervisor reviews each emergency; unjustified use suspends emergency rights.
  7. Scheduling: priority queue with aging.

Try these scenarios

  • Login as d2, request P100 as a routine request: denied. Switch to emergency: granted read-only minimum data. Try reading Billing or writing a note: denied.
  • Click “Fast-forward +10 min” three times and read again: token expired.
  • Login as n1, request emergency without an approver: denied. Add d2 as approver: granted.
  • Login as a1 and open emergency on P100: only billing, never medical data.
  • Login as s1, reject a case on the Review tab, then try the same emergency again as that user: suspended.
  • On the Audit Log tab, simulate tampering and verify the chain.
